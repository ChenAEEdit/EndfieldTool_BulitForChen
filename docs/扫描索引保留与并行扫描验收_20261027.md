# 扫描索引保留与并行扫描验收（2026-10-27）

## 实现

- “当前索引”选择器按来源切换已支持角色、扫描索引和导入索引。切换不会覆盖其他来源；扫描完成后自动选中新扫描结果。
- 最近一次成功扫描的索引和报告位置写入当前工作区 `index/last-scan.json`。启动时校验索引属于当前工作区且格式有效，再恢复到来源列表；损坏或越界的索引指针只显示提示，不触发重扫。报告丢失时仍恢复有效索引，并提示报告不可用。
- 设置页增加 1–8 路扫描设置，默认 4；旧设置缺少字段时仍使用 4。工作区切换后只恢复新工作区的最近扫描结果。
- 扫描器按独立 CHK 文件并行读取；缓存数据库由主线程访问，扫描完成的 CHK 独立提交缓存。取消或 worker 报错不会标记未完成 CHK，已提交缓存可继续复用。进度按总字节汇总，扫描报告记录并行路数和缓存复用数。
- 工作台版本为 `0.14.0-persistent-catalog-parallel-scan`。

## 验收结果

- 合成 CHK 测试：1、4、8 路的命中项和 SHA256 完全一致；缓存复用通过；模拟 worker 失败后，已完成 CHK 保留缓存，失败项未写入。
- 实际游戏样本：3 个 CHK，共 612,928,174 字节，两轮交替顺序运行。中位耗时：1 路 17.482 秒、4 路 17.561 秒、8 路 17.138 秒；六次输出和哈希一致。当前磁盘与 Python 环境下差异很小，4 路没有明显退化，也没有明显提速。
- 完整扫描器通过最终包的 `.NET → Python → 扫描器` 路径运行：42/42 个 CHK 命中缓存，工作线程参数为 4；生成的 152 个角色、2,674 项资源和 Bundle 依赖与已有索引一致。
- 恢复状态验证通过：有效索引可恢复；报告缺失时索引仍可恢复并给出提示；外部工作区路径和损坏 JSON 被拒绝且不触发重扫；旧设置默认并行数为 4。
- 正式包及 C# 验证程序构建均无警告、无错误。Python 并行扫描单元测试通过。

## 验证边界

完整扫描路径使用已缓存的 42 个 CHK 验证参数传递、缓存复用和结果一致性；强制全量重扫约需读取 42 GB，因此没有重复执行三次全量 I/O。并行速度对比使用真实的 613 MB CHK 样本并交替测试顺序。桌面鼠标自动化未运行；索引来源保留由工作台编译检查和底层来源/恢复状态测试覆盖。
