# 0.11.1：播放故障复现与修复记录

日期：2026-10-26。用户报告导入成功但无法播放，并要求自行创建 Unity 工程验证。

## 1. 实际原因

本次有两类问题。

### 生成入口与播放入口混淆

原 Unity 菜单只执行生成，需要选中 `adaptation.json`。未选中时抛出选择配置异常；选中一个已经完成生成的包后，又会因禁止覆盖旧内容而报错。这两个异常在新建工程中均已准确复现，原生成文件未被覆盖。

工作台原来只有定位场景等入口，没有直接打开正确场景并进入 Play 的按钮，容易让人重复执行生成菜单。

### 专属行走的主体肌肉通道被丢弃

用户最近生成的三个片段是：

- `A_actor_chen_customized_state_walk_end`
- `A_actor_chen_customized_state_walk_loop`
- `A_actor_chen_customized_state_walk_start`

每条源动画都有 2380 条绑定。旧通用流程统一生成 Generic，跳过其中 147 条 Animator 肌肉／根通道，只保留 2233 条 Transform 绑定。

实际 Play 时，时间可以推进，头发等附加骨骼也有变化，但大腿、上臂、脊柱的旋转均无变化，角色保持 T 字姿势。仅检查 Animator 时间和“有一些骨骼运动”的旧判定不足以证明主体播放正常，不能据此认定这些片段是附加动画。

本次加强检查：同时记录主肢体旋转和实际画面，避免将上述情况判断为主体播放成功。

## 2. 已修复内容

### 按真实主体通道选择播放方式

- 有动态主体 Transform 旋转的两条待机保留 Generic。
- 主体 Transform 旋转没有变化、但存在动态肌肉的三条专属行走使用 Humanoid，保留 Animator 肌肉及根通道。
- 当前主体检测使用已验证的 Bip001 主骨骼命名。其他骨架命名、静态人形姿势和不同游戏版本仍需补充适配与验证，不声称自动识别所有角色。
- 模型导出新增 `avatar_human_candidates.json`，记录同批实际资源中的源人形映射及 Avatar 名称、源资产、源 Bundle、PathID。
- 保留模型实际 Animator 引用的 Avatar 作为路径解析依据；另从源映射中选择唯一、全部骨骼名称与导入骨架匹配的映射，用当前导入静止骨架建立 Human Avatar。映射缺失或歧义时停止，不按相似名字猜测。
- 本次匹配来源为 `SK_actor_chen_01Avatar`，源资产 `CAB-3e3292ab6bcaf82592d4754706fc0277`，PathID `-5108097638540883993`。运行时 `humanScale` 为 `0.99172956`。
- 同一预览内按片段切换配套 Generic／Humanoid Avatar。

### 明确的打开播放入口

- 工作台新增“打开并播放预览”：先严格核对当前任务的已有结果，然后打开正确项目和场景并请求 Play。
- 已打开且入口脚本为当前版本的项目，可直接接收播放请求。
- 首次更新旧入口时，需要保存并关闭项目；工具按已记录摘要备份、更新入口。手工修改过、归属未知的脚本不会被静默覆盖。
- Unity 新增菜单 `Endfield Character Tool → 打开并播放动画预览`。
- 原生成菜单遇到完整且未修改的已有结果，改为打开预览，不重复写入生成物。
- 可以从包文件夹、配置、Prefab 或场景定位配置；当前场景属于包时也能识别。只有一个包时可自动定位；多个包且上下文不明确时提示选择。
- 打开场景会保留正常的未保存场景确认；已有其他场景正在 Play 时不会擅自停止。
- 默认优先播放可循环片段，避免首次显示结束片段后停在末帧。
- 新场景保存源动画显示名称，不再只显示 `Clip_编号`。
- 旧包若丢弃了必需的主体肌肉通道，会提示重新生成；不会通过简单打开旧结果把丢失的主体通道补回来。

### 结果保护

原生包配置版本升级为 `0.11.1`，继续支持旧 `0.8 / 0.9 / 0.10` 包的核对。新报告记录人形模式、动态肌肉数、主体旋转通道数、人形映射来源及 Human Avatar 输出。

工作台与 Unity 入口继续检查配置、源文件、生成文件和元数据摘要，并核对 Human Avatar 与片段播放模式的一致性。被修改或不完整的旧结果仍然保留。
