# 终末地角色工作台：框架预览 0.2.0

日期：2026-10-25。本次实现通用工具的界面与模块基础，未接入游戏全量索引或任意角色提取执行器。

## 1. 打开方式

独立运行目录：`D:/AAAChatGPT/EndfieldCharacterTool-Framework`。

双击其中的 `EndfieldChenTool.exe` 打开角色工作台。可执行文件暂时沿用既有工程名；窗口名称为“终末地角色工作台 · 框架预览 0.2.0”。

`D:/AAAChatGPT/EndfieldChenTool` 中的 v0.1.3 成品及原发布包未被覆盖。当前 Unity 项目未修改。

## 2. 当前能操作什么

| 页面 | 当前实现 |
| --- | --- |
| 角色与资源 | 加载已支持角色配置；按名称、代码、资源路径搜索；查看模型、Avatar、动作、来源与已知 Bundle 依赖；导入及另存 JSON 资源索引 |
| 提取计划 | 勾选资源，合并已知 Bundle 依赖；选择动画时自动包含该角色已收录的模型及 Avatar；保存独立任务计划 |
| 任务记录 | 从工作区读取已保存的计划，查看阶段状态，打开计划 JSON 文件 |
| 环境与已有工具 | 填写游戏、输出、Unity、Blender 路径，保存独立设置；打开既有陈千语提取窗口 |

首次加载的数据来自 `profiles/chen.json`，只有陈千语模型、Avatar 和两条行走。这表示工具已收录配置，没有执行游戏扫描，也没有重新证明资源能解码或播放。六条专属待机仍通过现有 Unity 项目场景／菜单访问。

可以先在“角色与资源”选择内容，再到“提取计划”保存；保存后会转到“任务记录”。界面中的“执行提取”按钮暂不可用。已有陈千语提取窗口沿用原有独立设置，不接收新任务计划。

## 3. 工作区和数据

新工作区默认：`D:/AAAChatGPT/EndfieldCharacterWorkspace`。第一次保存计划时建立，要求为空目录或已有兼容标识的角色工作区。它与旧工具工作区不同。

```text
EndfieldCharacterWorkspace/
  character-workspace.json       工作区格式标识
  tasks/
    <任务 GUID>/
      plan.json                 版本、来源、资源、已知依赖、环境选项和各阶段状态
```

设置保存在 `%LOCALAPPDATA%/EndfieldCharacterTool/settings.json`，与旧工具的设置分开。路径填写不代表检查通过；权重检查、Unity 预览和实际播放检查默认未请求。

索引格式标识为 `endfield-character-catalog-v1`，主要字段为：

| 字段 | 说明 |
| --- | --- |
| `gameBuild`、`gameAssemblySha256` | 来源游戏版本及预期摘要；导入不会核对本机游戏 |
| `sourceDescription`、`createdAt` | 来源描述及建立时间；界面另外记录实际导入路径 |
| `bundles` | Bundle 的 `id`、`group`、`md5` |
| `characters` | 角色 `id`、`displayName`、`rootName`、`rootPathId` 和 `resources` |
| `resources` | `id`、`name`、`kind`（Model／Avatar／Animation）、`sourcePath`、`rig`、`backendKey`、`bundleIds` |

角色、资源和 Bundle 标识不得重复，引用的 Bundle 必须存在，摘要格式必须有效。索引是元数据，不包含运行成功状态；资源路径在这一阶段只用于展示和计划，不用于执行程序。单个 JSON 读取上限为 32 MB，后续大规模索引应改为数据库或分页。

## 4. 模块划分

源码根目录：`D:/AAAChatGPT/2026-10-23/ni/EndfieldChenTool`。

```text
Framework/
  Domain/Contracts.cs           资源、角色、索引、计划、阶段状态和扩展接口
  Services/CatalogService.cs    现有配置读取、索引导入、结构校验、搜索
  Services/WorkspaceStore.cs    JSON 原子保存、计划生成、工作区与任务记录
  WorkspaceForm.cs             四个工作页面及交互
Program.cs                     默认进入工作台；保留既有陈千语窗口入口
pipeline.py                    既有陈千语提取流程，本次未改动
scripts/package_framework.ps1  独立编译与打包入口
```

扩展接口：

- `IResourceCatalogProvider`：目前实现角色配置读取和 JSON 索引读取；下一阶段实现游戏资源索引。
- `ITaskPlanner`：将角色与资源选择转成计划，合并配置中已有的依赖。
- `IExtractionBackend`：预留异步执行、进度和取消接口；本次没有执行器实现，不会生成模拟成功结果。

框架并不具备通用的 VFS 依赖图解析能力；目前的“依赖合并”仅针对配置／索引已经列出的 Bundle。动画模式仍作为元数据保留，尚未自动判定任意角色的 Generic／Humanoid。

```powershell

```

要求本机已安装 .NET 10 SDK，既有工程已还原依赖，并保留 `D:/AAAChatGPT/EndfieldChenTool` 的完整 v0.1.3 运行依赖。脚本使用现有依赖进行编译，不联网还原；若迁移到新电脑，应先准备 SDK、依赖和已交付工具包。

脚本仅构建和复制文件，不启动界面、解析器、Unity、Blender 或测试。输出目录必须与源码及旧成品独立；重复打包要求已有本框架的目录标识。

不要用包内的脚本直接重建整个开发环境：完整开发入口以 Git 源码仓库为准。原 `build_tool.py` 仍包含根据历史证据生成陈千语配置与模板的步骤，本阶段不运行它。

命令行默认或 `--workspace` 进入工作台，`--chen` 进入旧陈千语窗口；既有自动检查参数仍进入旧窗口路径，本次未运行它们。
