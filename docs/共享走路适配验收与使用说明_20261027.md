## 验收标准

- 对每个共享行走至少比较 25 个时刻，主体世界旋转最大误差不超过 0.25°；四元数连续性处理前后的源关键姿态差不超过 0.1°。
- 参考采样只在内存中处理非有限切线与四元数连续性，原始 `.anim` 文件不改写。主体参考基于真实候选及显式选择，不能用名称相关性认定兼容。
- 实际 Play 跨越循环边界；记录有限顶点、主体运动、全身/脸/膝盖画面、预览操作和保存重载结果。
- 轨道数与源通道数完全对应；未输出逐条说明。严格失败时拟保留项也显示为未输出。
- 骨轴反转、不完整四元数、歧义主体绑定、缺少语义映射、源摘要或轨道报告异常均必须拒绝。
- 长工作区路径完成导出、Unity 生成和播放；原生日志与回执归档校验一致。

## 操作步骤

1. 打开 `D:\AAAChatGPT\EndfieldCharacterTool-0.12.0\EndfieldChenTool.exe`；填写游戏和输出路径，选择与工程一致的 Unity 编辑器。
2. 选择角色及资源，生成并载入提取任务，解析实际对象。选择模型、实际关联 Avatar 和要播放的动作。
3. 本轮三个模型均使用模型导入倍率 **100**、动画位置倍率 **1**，请在高级设置核对。专属 Generic 动作保持默认直接绑定；共享动作显式选择有证据的源骨架候选。本轮女性共享样例使用 `SK_actor_female`，男性共享样例使用 `SK_actor_male`。同覆盖候选不会自动选定，其他骨架需另行验证。
4. 默认严格模式遇到缺少目标节点或参考证据会停止。明确接受部分轨道不输出时，勾选“忽略未匹配轨道并记录”，再生成新的独立适配包。
5. 保存并关闭目标 Unity 编辑器，点击“生成 Unity 预览”。完成后先看输出/未输出数量，再在同页“轨道明细”查看完整路径、属性及原因；可按名称、哈希搜索。
6. 点击“打开并播放预览”，观察完整循环、脸、手脚和膝盖。已生成内容不覆盖重建；修改规则后建立新包。

## 边界

- 显式省略轨道属于有损迁移；生成成功和主体姿态检查通过不代表原游戏 IK、实时布料、附件逻辑、材质与全部表情已还原。
- 尚未解析的哈希、目标没有的骨骼或缺少可靠辅助参考姿态应保留具体记录，不按猜测补齐。
- 源骨架候选设置作用于同次选择中的 Generic 动作。不同来源的 Generic 动作分批生成；切回专属动作时恢复直接绑定。Humanoid 动作使用真实人形映射，不执行共享 Generic 的参考姿态换算。
- 数值核对以所选候选和已解码数据为基准，不证明候选就是动画唯一的原始所属骨架；只对本轮实际验证过的组合给出结论。
- 验证只支持本轮记录中的游戏快照、角色和动作；其他角色、游戏更新及其他引擎需要相应验证。
- 旧版工具和用户 Unity 工程不自动覆盖；以最终交付目录和验收状态为准。
