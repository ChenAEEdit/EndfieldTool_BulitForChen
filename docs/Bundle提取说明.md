## 怎么使用

1. 打开完整工作台目录中的 `EndfieldChenTool.exe`，窗口版本应为 0.5.0。
2. 在“环境与已有工具”填写游戏、独立工作区及 Blender 路径。提取使用 Blender 自带 Python，不启动 Blender 应用。
3. 在“角色与资源”勾选内容。陈千语可以直接使用“加载已支持角色”，不必先做全游戏名称扫描；其他角色使用已有的有效索引。
4. 到“提取计划”点击 **执行 Bundle 提取**。工具先保存计划，再执行。
5. 在“任务记录”查看状态，通过“打开提取目录”“打开提取结果”查看实际输出；“运行日志”显示进度。

也可先保存计划，再选择该任务，点击 **继续／重试提取**。重试沿用计划记录的路径，修改环境页面不会改写历史计划。游戏程序或计划资源摘要变化后，应重新建立计划。

## 结果在哪里

默认工作区：`D:/AAAChatGPT/EndfieldCharacterWorkspace`。每个计划独立输出：

```text
工作区/tasks/<计划 GUID>/
  plan.json
  extraction.lock
  result.json                         最近一次实际执行结果／进度
  bundles/<VFS 分组>/<原 Bundle 名>.ab  完整、校验后的输出
  runs/<运行 GUID>/
    extraction.log
    result.json                       本次运行独立结果
    metadata/                         本次分组索引与资源清单
```

结果包含预期／实际文件数量、新提取／复用数量、每个文件的位置、长度、MD5、虚拟路径，以及程序／清单和计划摘要。历史运行保留在 `runs`，重试不覆盖旧运行目录。界面最多显示 200 条文件路径，完整列表见结果 JSON。

## 执行逻辑

1. 核对计划格式、任务 ID、工作区标识及计划位置，使用任务锁避免重复写入。
2. 核对当前 GameAssembly 与计划 SHA256，拒绝用旧计划提取已更新的游戏。
3. 读取实际 BLC，严格识别索引格式；提取并校验资源清单，解析依赖。
4. 以分组和完整虚拟路径定位资源。早期配置无虚拟路径时，仅在指定分组内按 basename 查找，要求唯一且 MD5 一致。
5. 从计划资源的 Bundle 引用出发，按当前清单重新遍历依赖图，处理循环；不直接信任导入计划声称的依赖完整性。
6. 提取前检查必要 CHK 的存在和长度，拒绝缺失、歧义及输出文件名冲突。
7. 已有输出重新检查长度和 MD5，符合预期才复用。新文件由原生程序流式读取、按需解密，并计算 MD5。
8. 新文件先写独立临时文件，校验成功且长度正确才替换正式文件。每个完整文件写入检查点。
9. 全部完成后再次核对游戏索引集合、BLC、GameAssembly 和计划，确认未变化后发布完成状态。

原生程序使用固定大小缓冲区，不将整个 Bundle 同时读入内存。校验针对文件内容，不只检查文件是否存在。

## 取消、失败与继续

- “取消提取”、运行日志中的“取消当前任务”和资源页的“取消任务”均可停止执行。关闭工作台会先停止当前任务及其辅助进程。
- 完整输出保留。再次执行时按文件重新校验并复用；当前中断文件重新处理，不提供文件内部字节级续传。
- 非正常终止可能留下 `.partial-<GUID>`，它们不列入成功结果，也不按正式文件复用。
- 同一任务采用操作系统锁，每次运行具有独立 ID。界面只接受本次运行的结果，不用旧报告冒充完成。
- 中断状态只修改属于本次运行的记录，不覆盖另一个进程的结果。
- 部分文件完成而后续失败时，整体仍为失败，完整文件列表保留供重试。

| 状态 | 含义 |
| --- | --- |
| 仅计划 | 尚无执行结果 |
| `running` | 处理中；若意外退出，可重试 |
| `cancelled` | 本次取消，完整文件保留 |
| `failed` | 未全部完成，查看结果和日志 |
| `bundles_extracted` | 全部所需 Bundle 校验完成，待对象解析 |

对象解码及动画适配标记为 `not_implemented`，权重、Unity 和播放检查为 `not_run`。工作台相关选项暂时禁用；旧计划即使记录了这些请求，本后端也只执行 Bundle 阶段。
