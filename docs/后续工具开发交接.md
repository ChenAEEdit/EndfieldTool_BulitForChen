通用角色搜索尚未实现；当前无需重新解包全部游戏，也不要为整理资料而重建 Unity 项目。

## 6. 必须保留的修复经验

1. **有文件不等于解码成功。** 早期 `.anim` 有零曲线／零关键帧的情况；ACL 解码和数据检查是必要步骤。
2. **单位、Avatar 比例与层级必须配套。** 不要给所有 FBX 套一个固定缩放值；用目标模型和源 Avatar 实测。
3. **路径能匹配仍可能改坏脸。** 共享 `female_walk` 曾覆盖陈千语面部常量，78/96 个面部蒙皮骨骼偏离，最大约 19.64 毫米。只对该共享预览过滤了 800 条标量曲线；源文件保留，专属待机保留其面部轨道。
4. **材质错误也会造成眼部异常。** 眼白辅助阴影曾误用衣服贴图；现为半透明基础替代材质，并未还原原游戏着色器。
5. **采样后恢复姿势再保存。** 编辑器采样改变 Transform；应恢复原始位置、旋转、缩放，保存后重载核对，避免把动画帧写成静止姿势。
6. **动画模式按片段确定。** 六条界面待机有完整 Transform 曲线，但 Humanoid 根数据会压低身体；已用 Generic 直接骨骼曲线，并排除 Animator 根／肌肉通道。这是当前六条片段的结论，不能推广到所有动画。
7. **无效插值需要记录处理。** 共享行走修过非有限切线、外部路径和 UI 根位置；记录来源与修正，不覆盖原始解码数据。
8. **数值正常不等于画面正确。** 包围盒和有限顶点检查不能替代脸部近景、全身审查及实际播放。
9. **布料片段不等于实时物理。** 附加片段需要已知基础层和参考姿势；原游戏求解器未重建，不能直接单播后认定还原成功。

## 8. 后续工具开发顺序（待授权启动）

1. **盘点现有解析能力和依赖。** 先读上述代码与报告，确认索引入口、版本识别、配置来源及打包过程；保留陈千语基线。
2. **实现并缓存资源索引。** 按游戏版本和资源摘要区分，支持恢复；不在每次搜索时全量导出。
3. **建立角色候选和关联资源列表。** 支持代码、名称、路径搜索；展示模型、Avatar、动作、依赖及来源。名称关联只能作为候选证据。
4. **支持按选择提取。** 解析依赖闭包，核对摘要，记录曲线、关键帧、缺失路径，保留原始资源与适配结果；支持取消、复用及继续执行。
5. **配置化角色和动作。** 移除固定根节点、网格数、贴图规则、动作列表和固定输出目录等假设；避免新角色覆盖现有陈千语资源。
6. **统一动画适配和预览入口。** 将已有待机能力接入界面，按证据选择 Generic／Humanoid，明确专属、共享、附加动作的处理规则。
7. **分阶段显示状态。** 分别记录“已发现、已解码、已适配、已验证”；未请求、未执行或不支持的步骤不能标为通过。
8. **在用户授权验证时，用其他角色确认通用性。** 先走一个不同角色的完整流程，再复查陈千语；不能仅凭陈千语仍能播放就宣称通用。
9. **提交和交付。** 按阶段提交 Git，更新依赖许可证、支持范围、使用说明及已知问题；发布包不包含游戏资源。

首版范围建议：本机当前游戏版本、角色和动作搜索、选取导出、依赖与状态报告、按需 Unity 预览。跨版本兼容、全套实时布料、IK、游戏着色器和跨引擎导出需另行确定范围。
