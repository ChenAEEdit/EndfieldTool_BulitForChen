## 3. 提取与修复流程

本次采用的流程是：

1. 核对游戏版本和资源摘要。
2. 从 VFS 中提取需要的 Bundle，并逐个检查 MD5。
3. 导出模型、贴图、骨架和 Avatar 元数据。
4. 用兼容当前资源格式的解析器解码动画，包括 ACL 压缩片段。
5. 根据 Avatar 路径表和实际导入层级映射骨骼。
6. 分别处理不同片段的单位、根位置、动画类型和面部轨道。
7. 采样检查网格，保存全身和面部画面。
8. 进入实际 Play 模式检查播放，再整理可用场景。

解包思路参考了 [HollowAmeChan/ZMD_unpack](https://github.com/HollowAmeChan/ZMD_unpack)，本机工具结合了兼容的模型导出器、AnimeStudio 相关解析代码和 Ruri.ACL 解码实现。第三方来源与许可证保存在工具包的 `THIRD_PARTY.md`、`licenses` 和源码目录中。

## 4. 之前为什么没有一次修好

### 4.1 解出了文件，不代表动画已经正确解码

早期导出的部分 `.anim` 文件虽然存在，但曲线和关键帧数量为零。这样的文件不能作为“提取成功”的证据。

后续接入 ACL 解码，并检查实际曲线、关键帧和未解析路径，才得到了有效动画数据。

### 4.2 单位和 Avatar 比例会影响整个身体

模型导入单位、动画位置单位及 Humanoid Avatar 的比例必须一致。此前链路中出现过单位和人形比例不一致的问题，会导致身体位移或蒙皮异常。

修复时使用实际导入骨架和源 HumanBone 映射建立所需 Avatar，并核对比例。已验证的 Humanoid 示例 `humanScale` 约为 `0.99173`。

这些设置针对当前导出链路，不能简单推广成所有 FBX 都应使用同一个缩放值。

### 4.3 路径匹配，不代表面部适配

共享 `female_walk` 带有与陈千语不同的面部固定变换。即使骨骼名称相同，直接应用也会改变脸型。

对照实验中，96 个面部蒙皮骨骼有 78 个偏离原始姿势，最大位置差约 19.64 毫米，出现眼球露白、嘴唇和脸颊变形。

处理方式：

- 根据面部网格实际使用的骨骼及祖先确定 98 个相关节点。
- 在共享行走预览中排除对应的 800 条标量曲线，保留原始中性面部。
- 保留源动画文件，修正只应用于生成的预览片段。
- 对角色专属待机保留其面部轨道，不套用共享行走的过滤规则。

### 4.4 眼睛上的彩色横条来自错误材质

基础材质映射曾将 `M_eyewhiteshadow_common_01` 误配到衣服贴图 `T_actor_chen_cloth_01_D`。

改用半透明的基础阴影替代材质后，眼睛上方的彩色横条消失。这个处理用于预览，没有完整重建游戏原着色器。

### 4.5 动画采样会改动编辑状态中的骨骼

检查程序调用 Animator 采样动画后，骨骼 Transform 已经发生变化。旧逻辑又采样第 0 帧并保存场景，因此尚未播放就会看到抬手、弯腿的姿势。

修复后先恢复原始位置、旋转和缩放，再保存并重新加载核对。四个相关场景各检查 459 个内部节点，恢复后均与原始 FBX 姿势一致。

### 4.6 待机不能只凭 Humanoid 通道判断播放方式

总览待机同时存在完整的骨骼 Transform 曲线和 Humanoid 数据，但其中 Humanoid 根位置为零。对照发现，直接按 Humanoid 播放会把身体压低并改变姿势。

本次六条界面待机采用 Generic，使用直接骨骼曲线，排除 Animator 根／肌肉通道，保留专属面部与头发轨道。全身位置和姿势随之恢复正常。

### 4.7 之前的验证范围不足

整体包围盒合理、没有无效顶点、腿部在运动，只能排除一部分故障。厘米级的面部错位仍可能通过这些检查。

因此补上了面部近景、面部节点检查、循环接缝、实际播放和保存后姿势检查。此前将部分“播放检查通过”表述得过于宽泛，这是需要纠正的地方。
