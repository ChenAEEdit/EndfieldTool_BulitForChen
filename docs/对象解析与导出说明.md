# 对象解析与导出预览 0.6.1

日期：2026-10-25。

本阶段支持从已提取 Bundle 中列出实际对象、精确选择模型和动画，以及导出 FBX／原始 `.anim`。0.6.0 初版仅完成编译；随后按用户要求实际验证并修正为 0.6.1：工作台模型加八条动画导出、两条动画单独导出、对象筛选及 Avatar 对应检查均完成。证据见[对象导出验证记录](D:/AAAChatGPT/2026-10-23/ni/EndfieldChenTool/docs/对象导出验证记录.md)。没有执行 Unity 导入或播放验证。

## 1. 怎么使用

运行入口：`D:/AAAChatGPT/EndfieldCharacterTool-Framework/EndfieldChenTool.exe`，窗口应显示“对象导出预览 0.6.1”。请保持整个工具目录完整。

1. 在“环境与已有工具”填写游戏、独立工作区和 Blender 路径。Blender 自带 Python 用于执行流程；此阶段不启动 Blender 界面或写入 Unity 项目。
2. 从已有配置或扫描得到的名称候选选择资源，保存计划并执行 Bundle 提取。名称候选可能遗漏资源；确保计划包含所需模型、骨架和动画的 Bundle 及依赖。
3. 在“任务记录”选择状态为“Bundle 已提取”的任务，点击“解析 Bundle 对象”。程序检查文件长度与 MD5，建立本次只读解析快照，读取实际 GameObject、Mesh、Avatar、AnimationClip。
4. 在“对象与导出”核对名称、PathID、来源资产和来源 Bundle。下拉选择模型根节点；右侧勾选动画。也可以只导出模型或只导出动画。默认不选模型或动画。
5. 选择模型后，仅当其 Animator 实际引用了已读取的 Avatar，界面才自动选中该 Avatar。没有明确引用时可手工选择，但不保证适配正确。已知引用与手工选择不一致时会拒绝导出。
6. 点击“导出所选对象”。成功文件及部分失败分别记录；点击“打开导出目录”或“打开对象报告”查看。
7. 重新打开工具后，在任务记录中选择原任务，点击“载入已有对象列表”继续选择。若重新提取 Bundle 或修改计划，应重新解析对象，避免使用旧快照。

筛选同时影响实际对象表和动画列表。每个列表最多显示 2000 项，可继续输入名称、类型、PathID 或来源缩小范围；隐藏的勾选保留并计入导出数量。“勾选当前动画列表”只作用于当前显示项，“清空全部动画勾选”也会清除隐藏项。

## 2. 输出是什么

| 内容 | 含义 |
| --- | --- |
| 对象列表 | 实际解析到的对象，不再只是扫描到的明文名称；仍需人工确认角色和动作是否配套 |
| 模型 FBX | 所选根节点层级的模型、蒙皮、材质及可解析贴图；不含动画，不保证复原游戏专用着色器、布料或 IK |
| 原始 `.anim` | 所选 AnimationClip 的解码结果；若选择 Avatar，仅用其路径表解析已知哈希路径 |
| 模型／动画报告 | 来源、PathID、外部引用、曲线与关键帧数量、未知路径和失败原因 |
| 对象操作结果 | 每次独立运行状态、文件、长度和 SHA256；明确标记 `adapted=false`、`playbackVerified=false` |

**原始动画不等于可直接播放的动画。** 尚未处理不同模型的单位、根节点路径、Generic／Humanoid 播放模式、共享面部轨道、附加层与参考姿势。未知路径保留并提示，不把它们随意绑定到其他角色。动画中的缺失路径、非有限插值或不正确的播放模式仍可能使姿势异常。

列表里的骨骼引用合计包含各蒙皮渲染器重复引用，不是去重后的骨骼数，也不是权重检查结果。Avatar 路径表不是完整骨架／权重正确性的证明。

## 3. 工作区结构

```text
tasks/<任务 GUID>/
  plan.json                         原任务计划
  result.json                       最近一次 Bundle 提取结果（不由对象操作改写）
  bundles/<分组>/*.ab                经校验的 Bundle
  extraction.lock                   同任务提取／解析／导出的互斥锁
  objects/
    result.json                     最近一次对象操作结果
    <运行 GUID>/
      operation.json                本次结果与真实状态
      objects.log                   解析器／导出器输出及诊断
      input/*.ab                    解析时复制并校验的 Bundle 快照（解析运行）
      inventory.json                对象清单及来源、快照摘要（解析运行）
      avatar-<对象标识>.json         对应 Avatar 的哈希路径表（解析运行）
      selection.json                用户选择（导出运行）
      clips.json                    动画精确身份（导出运行）
      model-report.json             模型导出报告（按请求生成）
      animation-report.json         动画导出报告（按请求生成）
      exports/model/                FBX、贴图、材质／Avatar 元数据
      exports/animations/            原始动画
```

每次操作新建运行目录，保留来源和旧结果；对象导出不提供逐动画断点恢复。取消后可重试，Bundle 提取的文件级恢复仍可使用。快照会增加磁盘占用，程序暂不自动清理。

## 4. 防止选错与复用错误

- 对象身份包含实际来源 Bundle、序列化资产文件和 64 位 PathID；PathID 在对象清单中用字符串保存。
- 严格模型选择必须唯一，动画选择必须全部找到；不会按同名资源取第一个。导出动画名附带 PathID 和来源摘要，避免覆盖同名片段。
- 不同内容的 Bundle 若重名，当前解析库不能可靠区分，会拒绝解析；不会静默丢弃一个文件。
- 导出前后核对输入快照文件集合与 MD5，并核对任务、Bundle 运行记录、计划 SHA256；Avatar 路径表另核对 SHA256。
- 本阶段不合并无关模型的层级来猜测动画路径；仅显式选择的 Avatar 提供额外路径解析。
- 子进程退出、完成事件、本次运行编号、输出路径及长度必须一致；部分失败不会标成全部成功，旧报告不会证明本次完成。
- 同一任务共享互斥锁；取消会停止子进程树并保留运行记录。工作台内扫描、提取和对象操作互斥。

## 5. 源码和构建

源码仓库：`D:/AAAChatGPT/2026-10-23/ni/EndfieldChenTool`。

| 文件 | 职责 |
| --- | --- |
| `Framework/ObjectPage.cs` | 实际对象列表、筛选、选择、导出和报告入口 |
| `Framework/Services/ObjectWorkflow.cs` | 异步进程、取消、运行隔离与结果核对 |
| `scripts/object_pipeline.py` | 输入快照、摘要检查、精确选择及导出编排 |
| `sources/exporters/BundleObjectProbe` | 从实际 Bundle 列出对象和明确的 Animator → Avatar 引用 |
| `sources/exporters/ModelExportCompat` | 模型严格身份选择和 FBX 导出，保留原专用调用方式 |
| `sources/exporters/AnimationExportCompat` | 动画精确选择、ACL 解码和显式 Avatar 路径解析，保留原专用调用方式 |
| `scripts/package_framework.ps1` | 构建与打包，复制全部依赖和当前源码 |

新增运行组件使用独立目录：`runtime/object-probe`、`runtime/object-model`、`runtime/object-animation`。模型使用旧的模型解析库；对象清单和动画使用带 ACL 补丁的库。两个版本不能混放；旧专用流程的 `runtime/model`、`runtime/animation` 保留原组件。

导出器工程以仓库内 `runtime/model`、`runtime/animation` 为默认引用位置，可用 `RuntimeRoot` 覆盖。运行库不提交 Git；迁移构建需保留已有完整工具依赖。打包使用离线 NuGet 配置，不下载新依赖，也不启动导出或检查。

`sources/exporters/RuntimeDependencies.props` 将对应运行目录的托管依赖纳入 `.deps.json`，避免仅复制 DLL、却遗漏解压或纹理编解码组件的加载声明。原生 DLL 由打包脚本随运行目录复制。

补齐依赖声明后发现，历史动画运行目录携带 ZstdSharp 0.8.6，但带 ACL 补丁的 AnimeStudio 要求 0.8.8。本次从本机既有 NuGet 缓存取用 0.8.8，修正源码仓库的动画构建依赖，再随新版对象组件分发；旧 v0.1.3 成品未覆盖。模型组件仍使用配套的 0.8.6。打包将程序集版本冲突视为错误；迁移构建请从新版 `runtime/object-animation` 准备动画依赖，不要直接沿用旧包中的混合版本目录。
