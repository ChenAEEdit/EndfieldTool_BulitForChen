后续更新：0.5.0 已接入按计划执行的 Bundle 提取，见[Bundle 提取说明](D:/AAAChatGPT/2026-10-23/ni/EndfieldChenTool/docs/Bundle提取说明.md)。本文件保留 0.4.0 兼容性设计基线，资源映射和对象导出仍待完成。

## 1. 本次通用化的范围

本次将**索引读取与发现模块**从“只接受固定 GameAssembly 摘要”改成“识别格式并严格校验”。这提供跨版本的兼容基础，不代表已经完成任意角色导出，也不承诺未知加密、容器或动画格式都能读取。

角色到资源的精确映射仍未补齐；此前的名称扫描保留为辅助候选发现。后续优先补齐资源哈希／已知路径到 Bundle 的映射，再接对象与骨架确认、选择性提取。

## 2. 用户如何操作

1. 打开 `D:/AAAChatGPT/EndfieldCharacterTool-Framework/EndfieldChenTool.exe`。
2. 在“环境与已有工具”填写游戏目录及独立工作区。
3. 点击“检查索引兼容性”。该操作读取 BLC 和资源清单，解密／解压并校验元数据，不进行大范围名称扫描。
4. 在“扫描记录”查看结果或打开本次检查报告。需要候选名称时，再点击“扫描游戏资源”。

检查时只读游戏文件；工作区会保存解码后的索引、清单、报告和日志。检查需要本机 Python、.NET 辅助组件及可读取的 GameAssembly，并不支持不含此结构的其他平台安装。

## 3. 状态如何解释

| 状态 | 界面解释 | 含义 |
| --- | --- | --- |
| `KnownReference` | 匹配历史参考版本，索引格式可读 | 程序 SHA256 与清单 MD5 均匹配参考记录，且本次严格格式解析成功 |
| `FormatCompatibleUnverified` | 索引格式可读，新版本尚未验证 | 与参考组合不匹配，但现有适配器能读取并校验索引；允许继续候选发现 |
| `Unsupported` | 暂无适用格式适配器 | 当前头部不匹配已注册格式；不会套用其他布局继续猜读 |
| `Unreadable` | 数据或环境无法读取 | 文件缺失、解压失败、MD5 不符、字段／引用校验失败或环境问题，具体原因在报告和日志 |
| `Unknown` | 尚未检查当前安装版本 | 旧索引或只加载角色配置，没有本次安装的格式检查记录 |

格式可读与模型、动画可正确解码是不同的结论。报告中的 `decoded`、`adapted`、`verified` 仍为 false。历史参考匹配也不替代新任务的实际播放检查。

仅检查兼容性不会将当前界面已有的旧角色索引升级成新版本索引。新索引完成后才替换角色列表，避免把旧数据的归属改错。

## 4. 模块划分与扩展

- `scripts/index_formats.py`：格式适配器及选择逻辑，独立于角色配置。当前注册 `blc-v4-29047701` 与 `manifest-refvalue-bundle48-v1`。
- BLC 适配器先识别版本及标记，再复用严格解析器检查记录数量、文件边界、分组长度及尾部。
- 清单适配器复用完整布局校验，并主动读取全部 Bundle，核对记录步长、共享引用和依赖索引，而不是只检查文件头。
- `profiles/known_builds.json`：历史参考的程序／清单组合，只用于显示已知状态，不是读取许可。缺少该文件时，可读索引仍归为未验证版本。
- 新的加密或布局变化仍需添加实际解码器及适配器代码；不会通过删掉边界检查或改版本数字来声称兼容。
- `Framework/Services/GameResourceIndexer.cs`：兼容性检查及扫描的子进程入口、取消、日志和失败报告。
- `Framework/Domain/Contracts.cs`：索引及任务计划新增兼容性状态与说明，保留来源。

`pipeline.py` 的旧陈千语提取配置仍包含固定 Bundle 与 Avatar 假设，因此继续锁定历史版本。把它解除限制会误用旧资源配置，本次没有这样处理。通用索引可读的新版本不能直接交给旧提取流程。

## 5. 缓存隔离与更新

```text
工作区/index/
  scan.lock
  logs/
  <完整 GameAssembly SHA256>/
    plaintext-candidates-v2/
      strict-index-adapters-v1/
        metadata/                       分组索引与解压清单
        compatibility-<GUID>.json        独立的格式检查报告
        failure-<GUID>.json              后续扫描失败时的报告
        generations/
          <清单、BLC摘要和格式组合的SHA256>/
            chunks.sqlite
            catalog.json
            report.json
```

程序更新会进入新的程序摘要目录；仅热更新资源时，即使程序没有变化，只要 BLC／清单变化也会进入新的代次。格式适配器升级同样隔离缓存，避免误用旧解析结果。此前 0.3.0 缓存保留，不冒充新格式检查结果。

每个代次内部仍按 CHK 长度／修改时间、BLC 摘要及扫描版本复用完整提交的记录；强制重新扫描可跳过 CHK 复用。发布前再次核对有效分组集合、BLC 摘要和 GameAssembly，发现安装正在变化时不发布结果。
