# 陈千语两条行走的膝部诊断

日期：2026-10-25。用户反馈行走时膝盖附近网格扭曲，并要求两条行走都检查。本次使用现有项目 `D:/Unity 3D/Projects/Codex_ZMD`，在 Unity 6000.0.84f1 中采样和截图，没有启动 Blender。

## 1. 当前结论

**共享 `female_walk` 的膝部修正轨道会明显增加当前陈千语模型的局部拉伸。** 保留当前播放模式、Avatar、主体行走和原模型权重，只移除膝部 `corrective_Knee` 轨道时，局部拉伸指标降低。证据指向共享辅助骨骼轨道不适合直接套用当前预览；尚未重建游戏中的修正求解器，不能据此宣称完全还原游戏效果。

专属 `customized_state_walk_loop` 不适合同样过滤：保持它当前 Humanoid 播放模式后，移除同类轨道使局部指标略变差。直接将专属原始源动画改为 Generic，指标也更差。因此没有把共享动作的候选处理套用到专属行走。

没有修改模型顶点或权重。对原工具目录中的模型、动画、场景、控制器和相关元数据共 54 个文件核对前后 SHA256，变化数为 0。

## 2. 对照方式和数据

每条动作采样 25 个时刻，膝部区域为原始姿势下距离左右小腿根节点 12 厘米内的网格顶点。选择两端均在区域内、原长大于 0.1 毫米的 7,835 条边，比较采样后与原姿势的边长比。

表中是每个时刻边长比第 99 百分位的**全周期最大值**，属于局部对照指标，不是美术正确性的标准阈值。

| 动作／处理 | 局部拉伸比 P99 的周期最大值 |
| --- | ---: |
| 共享行走，当前预览 | 2.216 |
| 共享行走，原始源直接骨骼采样 | 2.215 |
| 共享行走，保留当前播放模式，仅移除膝部修正轨道 | 1.444 |
| 专属行走，当前 Humanoid 预览 | 1.420 |
| 专属行走，原始源直接骨骼采样 | 1.639 |
| 专属行走，保留当前 Humanoid，仅移除膝部修正轨道 | 1.455 |

共享候选的上述最大值降低约 35%。区域内严重压缩边占比的周期最大值从约 0.804% 降至 0.153%。它仍可能存在自然弯曲或残留形变，不能简单把比值等于 1 当作所有姿势都应满足的条件。

第一轮广泛对比曾将“去修正轨道”与“改为直接骨骼播放”同时处理。最终报告改为 AnimatorOverrideController，仅替换原控制器的动画，在相同播放模式下单独移除修正轨道。以上使用最终这轮数据，避免混淆播放模式与轨道本身的影响。

## 5. 后续处理边界

本次已定位共享动作的一项明显影响因素并提供候选。专属动作尚未定位另一项需要修改的根因，不会为降低一个数字而随意改权重或全局关闭辅助骨骼。后续应结合用户看到的具体时刻和膝盖近景，再检查专属动作的修正骨骼、扭转分配及游戏求解器。
